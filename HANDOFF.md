## 1. Что это и зачем

Лендинг с **донат-голосованием за исторические видео про американскую политику**. Автор и фотограф — **Евгений Фельдман** (журналист).

Механика:
- Донат от **€7** = билет на закрытый онлайн-эфир + голос за конкретное видео.
- Когда видео набирает **€100**, автор назначает дату эфира и рассылает ссылку всем, кто голосовал.
- После эфира видео уходит в **«Архив показов»**, где запись продаётся от **€5**.

Смысл для автора: аудитория сама голосует деньгами, какой архивный материал он разберёт следующим. Показы идут на английском с русскими субтитрами.

## 6. ★ Авто-архив по времени — ключевой механизм

Чтобы автору не приходилось быть у компьютера в момент эфира, переходы идут по расписанию.

**`api/_schedule.js`** — единственный источник правды для бэка:

```js
const SCHEDULE = {
  '1960': { archiveAt: '2026-07-24T19:00:00Z', recording: 'https://youtube.com/live/_Pug1m4CGSU' },
  '1992': { archiveAt: '2026-08-27T20:00:00Z', recording: null },
};
```

**Фронт** держит те же моменты в data-атрибутах карточки в `index.html`:

```html
data-air-date="Эфир 27 августа · 21:00 Мск / 14:00 НЙ"   текст на карточке
data-live-at="2026-08-27T18:00:00Z"                      старт эфира (UTC)
data-archive-at="2026-08-27T20:00:00Z"                   эфир + 2ч (UTC)
data-past-meta="Эфир состоялся 27 августа"               подпись в архиве
```

Функция `applyLifecycle()` в `app.js` считает фазу от `Date.now()`:

1. **до `live-at`** — обычная won-карточка с датой эфира;
2. **между `live-at` и `archive-at`** — карточка скрывается (`hidden`), идёт эфир;
3. **после `archive-at`** — карточка пересобирается в разметку `.card-past` и переезжает в секцию `#archive` («Архив показов»), продаётся как запись.

Переходы срабатывают и по `setTimeout`, если вкладка открыта через границу.

> **Даты дублируются в `index.html` и `_schedule.js`** — статика не может `require` модуль. При переносе даты правь **оба места** и проверяй `grep` на остатки старой.

Москва = UTC+3 круглый год. Нью-Йорк летом EDT = UTC−4 (разница с Москвой 7 часов).

## 7. Ссылка на запись — важная логика безопасности

После эфира запись продаётся за деньги, поэтому ссылка **не должна быть видна до оплаты**.

- ❌ **Никогда не класть ссылку в `product_data.description`** — это поле Stripe рендерит на странице оплаты. Такая утечка уже случалась 24 июля: запись можно было посмотреть бесплатно, просто открыв форму оплаты. Исправлено в `7d82c2c`.
- ✅ Ссылка доходит до покупателя двумя путями:
  1. **success-страница** — через `/api/session`, поле `recording` (отдаётся только если `isArchived`);
  2. **чек Stripe** — через `payment_intent_data.description`. Это поле задаёт `charge.description`, попадает в автоматический email-чек и **не** показывается на странице оплаты.

Проверка после изменений: создать сессию через `/api/checkout` и поискать ссылку в `document.documentElement.outerHTML` страницы Stripe — её там быть не должно.

**Если `recording` ещё `null`, а `archiveAt` уже прошёл** — тексты автоматически переключаются на честное «Ссылку на запись пришлём на email» (и на Stripe, и на success). Ничего не ломается, но ссылку тогда рассылать вручную.

## 8. Поток платежа

1. Клик → `app.js` шлёт `POST /api/checkout` с `{video_id, amount}`.
2. `/api/checkout` определяет состояние, проверяет минимум, создаёт Stripe Session с `metadata.video_id`, возвращает URL.
3. Юзер платит на Stripe.
4. Stripe шлёт `checkout.session.completed` на `/api/stripe-webhook`.
5. Вебхук после проверки подписи:
   - дедуп по `event.id` через KV (SET NX, TTL 1 день);
   - **параллельно** пишет строку в Sheets и инкрементит сумму в KV;
   - шлёт Telegram с актуальной суммой; при первом пересечении €100 — отдельное «🏆»;
   - при ошибке **освобождает claim** (`releaseEvent`), чтобы ретрай Stripe не отдедупился и платёж не потерялся;
   - отвечает 200.
6. На success-странице `success.js` дёргает `/api/session` + `/api/totals?fresh=1`.

**Вся работа делается ДО ответа Stripe.** Vercel убивает функцию после `res.json`, фоновые задачи не успевают.

Через этот же Stripe-аккаунт идут платежи **других проектов автора**. Поэтому и вебхук, и `/api/session` фильтруют по своей мапе `VIDEOS` — чужие события игнорируются, чужие email не отдаются.

## 10. Типовые операции

### Добавить или заменить видео — 5 мест + картинка
1. `index.html` — карточка (порядок хронологический);
2. `api/checkout.js` — `VIDEOS`;
3. `api/session.js` — `VIDEOS`;
4. `api/stripe-webhook.js` — `VIDEOS` **и** `TAGS`;
5. `api/_kv.js` — `VIDEO_IDS`;
плюс `images/<id>.jpg` и строки `video.<id>.title/desc` в `texts.csv`.

> **`VIDEO_IDS` забыть нельзя**: `incrementTotal` фильтрует по этому списку — без записи донаты на новое видео молча не считались бы (платёж прошёл, счётчик стоит).

Новый id безопасен для KV: ключа `total:<id>` ещё нет, `readTotals` отдаст 0. `null` вместо всех тоталов возвращается, только если пусты **все** ключи.

### Назначить дату эфира
Автор пишет «эфир такого-то в столько-то по Москве» →
1. `STATE_OVERRIDES[id] = 'won'` в `api/checkout.js` (если ещё не стоит);
2. в `index.html` — `data-air-date`, `data-live-at`, `data-archive-at` (эфир + 2ч), `data-past-meta`;
3. в `api/_schedule.js` — запись с `archiveAt`;
4. когда появится ссылка на трансляцию — вписать её в `recording`.

### Правки текстов
Автор присылает `texts.csv` с заполненной колонкой «Стало» — применить в код. При правке CSV **не переписывать файл целиком** через `csv.writer` (меняется стиль кавычек во всём файле и раздувается дифф) — заменять строки точечно.

### Посмотреть/поправить суммы в KV
```bash
curl "https://smotrimvmeste.vercel.app/api/admin" -H "x-admin-secret: <ADMIN_SECRET>"
curl -X POST "https://smotrimvmeste.vercel.app/api/admin?action=reset&video=XXXX&to=0" -H "x-admin-secret: <ADMIN_SECRET>"
```
Секрет принимается **только** заголовком (в query-string он попадал бы в логи Vercel). Стоит rate limit 10/мин на IP **до** проверки секрета.

3. **Рефанды не вычитаются из тоталов.** `session.payment_status` остаётся `paid` после возврата. В реальности рефандов на донатах не бывает, но при тестовых возвратах цифры завышаются — правится вручную через `/api/admin`.
4. **Нет своей email-рассылки.** Ссылки победителям и покупателям записей автор шлёт руками на основе Google Sheets. Автоматизация потребовала бы почтового сервиса (Resend/Postmark) — в стеке его нет.
5. **Нет админки UI** — только curl к `/api/admin`.
6. **Нет кастомного домена** — живём на `vercel.app`.

### 🟢 Технический долг и дрейф

7. **Дата эфира дублируется** в `index.html` и `api/_schedule.js`. Рассинхрон = карточка исчезнет в одно время, а цена сменится в другое.
8. **`.env.example` устарел** — см. раздел 9.
9. **`texts.csv` местами разошёлся с сайтом:** `past.section.title` = «Прошлые эфиры» (на сайте «Архив показов»), `past.meta` = «Эфир проведён 7 мая» (на сайте «Эфир состоялся 24 июля»), `stripe.product.description.past` не учитывает вариант без ссылки.

12. **Скриншоты в браузерной панели ниже сгиба приходят пустыми** (артефакт окружения). Проверять вёрстку надёжнее через DOM-замеры (`getBoundingClientRect`, `getComputedStyle`), а не глазами по скриншоту.

## 13. Что не ломать

- **Структуру карточек** `.card > .card-year + .card-body > .card-image + h2 + .desc + .progress + .row` — `app.js` жёстко завязан на эти селекторы.
- **Ключи `VIDEOS`** = `metadata.video_id` в Stripe. Менять = терять связь с прошлыми платежами.
- **Ключи KV**: `total:<video_id>`, `evt:<event_id>`, `rl:<bucket>`.
- **Имена env vars** на Vercel.
- **`[hidden] { display: none !important; }`** в начале `style.css` — без него атрибут `hidden` не побеждает `display:grid` у `.card` и `display:flex` у `.thanks-row`, и скрытие карточки во время эфира не работает.
- **`CDN-Cache-Control`** (не `Cache-Control`) — специфика Vercel, обычный заголовок он переписывает.
- При сборке разметки в JS **не вставлять `url("…")` в атрибут `style="…"`** — двойные кавычки обрывают атрибут. Ставить через `el.style.backgroundImage`.

## 14. Как проверять изменения

Локального дев-сервера у проекта нет (serverless-функции локально не поднимаются без `vercel dev`). Практика, которая работала:

- **Фронт**: скопировать статику во временную папку, поднять `python3 -m http.server`, открыть в браузерной панели. `/api/*` будет отдавать 404 — это нормально. Суммы можно подложить через `localStorage.setItem('lastTotals', JSON.stringify({...}))`, их читает `applyCachedTotals()`.
- **Фазы жизненного цикла**: сделать копии `index.html` с подменёнными `data-live-at` / `data-archive-at` на прошлые/будущие даты и проверить все три состояния.
- **Бэк**: `node --check` на файлы + прямые `curl` к проду после деплоя (проверять коды ответа и минимальные суммы).
- **Прод после деплоя**: HTML кэшируется CDN, проверять с cache-buster и заголовком `Cache-Control: no-cache`.
